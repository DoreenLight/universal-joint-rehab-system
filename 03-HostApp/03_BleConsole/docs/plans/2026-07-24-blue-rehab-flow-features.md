# 蓝色“掌屈 / 背伸”康复流程开发清单

## 范围与约定

- [x] 本阶段只实现预设图中的蓝色流程：开始训练 → 掌屈/背伸 → 被动/主动 → 参数设置 → 实时训练。
- [x] 速度统一使用已确定的三档：低速 `20`、中速 `40`、高速 `80`；不采用预设图中的示例数值。
- [x] 被动模式由设备按目标位置和速度带动运动。
- [x] 主动模式是用户主动带动机构运动，电机只提供可控阻力/阻尼，不主动拖动用户。
- [x] 主动模式可选择“关节电机 + 齿轮电机”“仅关节电机”“仅齿轮电机”。
- [ ] 在协议文档中固定单位：齿轮电机位置/速度使用 IMU 角度 `°`、`°/s`；关节电机内部单位需在 BLE 边界明确换算，界面统一显示为用户可理解的角度/档位。

## 已实现的 UI 与流程骨架

- [x] 新增“康复训练”入口页及蓝色主题样式。
- [x] 新增训练方向选择页。
- [x] “掌屈、背伸”入口可用，尺偏/桡偏、旋内/旋外、环转暂时禁用。
- [x] 新增掌屈/背伸的“被动康复训练”和“主动康复训练”选择页。
- [x] 新增训练参数页。
- [x] 训练组数支持 `1～99`，默认 `6` 组。
- [x] 速度档位显示为 `20 / 40 / 80`，默认中档 `40`。
- [x] 主动模式提供低/中/高三档阻力选择。
- [x] 主动模式提供训练电机选择：双电机、仅关节电机、仅齿轮电机。
- [x] 被动模式自动禁用阻力和训练电机选择。
- [x] 实时训练页能够显示模式、组数、速度、阻力、训练对象和训练时长。
- [x] 实时训练页已有暂停/继续、结束训练、紧急复位到 `0°` 按钮。
- [x] 被动模式已经连接既有参数下发、开始和停止接口。
- [x] 主动模式当前明确标记为“流程预览”，不会误下发未经验证的力矩。

## UI 仍需完善

- [ ] 修复并统一检查源码、构建产物中的中文编码，确保所有标题、日志和按钮无乱码。
- [ ] 参数页根据模式显示准确名称：被动为“电机速度”，主动为“辅助速度上限/保护速度”，避免用户误认为主动模式会主动带动。
- [ ] 阻力档位在标定完成前只显示“低/中/高”，不要在 UI 中填入未经测试的 N·m 数值。
- [ ] 增加连接状态门禁：BLE 未连接、设备未就绪或心跳超时时，“开始训练”不可点击。
- [ ] 开始主动训练前增加确认摘要：目标电机、阻力档、速度保护档、组数。
- [ ] 实时页分别显示关节电机与齿轮电机的当前角度、速度和当前阻力输出。
- [ ] 实时页显示训练状态：准备、运行、暂停、完成、急停、通信故障、传感器故障。
- [ ] 实时页显示实际完成组数，不只显示预设组数。
- [ ] 暂停后修改参数的行为固定为：已运行会话保持原参数；结束并重新开始后才应用新参数。
- [ ] “结束训练”与“紧急停止/复位”在颜色、位置和确认逻辑上明确区分。
- [ ] 训练完成后自动停止计时、显示完成结果，并返回开始页或结果页。
- [ ] BLE 断开时立即冻结界面状态、显示原因，并禁止“继续”沿用过期会话。

## BLE / ESP32 / 中继协议

- [ ] 为主动训练分配独立命令，不复用被动位置控制命令。
- [ ] 定义主动参数帧：模式、目标电机位掩码、阻力档、速度保护档、训练组数、会话编号、校验。
- [ ] 定义主动控制帧：开始、暂停、继续、正常结束、紧急停止。
- [ ] 定义状态上报帧：已接收、参数有效、运行状态、完成组数、故障码、急停来源。
- [ ] BLE 必须等待 STM32 参数确认后才能把 UI 切换为“运行中”。
- [ ] 命令增加会话编号或序列号，防止断线重连后执行缓存的旧“开始”命令。
- [ ] ESP32 和 MiddleBoard 只做透明可靠转发，不自行解释或改变力矩参数。
- [ ] 保持现有实际链路配置并形成记录：ESP32/MiddleBoard 输入段与 MiddleBoard/F407 输出段各自波特率不得凭猜测修改。
- [ ] 增加端到端协议测试：每个主动命令均验证 BLE 发出、ESP32 接收、中继转发、F407 确认。
- [ ] 对错误长度、错误校验、未知命令、重复帧和超时帧进行拒绝测试。

## 待实现：主动阻力固件

- [ ] 先建立只读观测模式：采集两台电机的位置、速度、电流/力矩估计及 IMU 数据，但输出力矩保持为零。
- [ ] 确认关节电机支持的力矩/电流控制接口、反馈频率和正负方向。
- [ ] 确认齿轮电机支持的力矩/电流控制接口；若驱动器只支持速度/位置模式，不得用位置对抗伪装成阻力模式。
- [ ] 分别标定两台电机的“用户掌屈/背伸方向”和正负力矩方向。
- [ ] 为关节电机实现阻尼律：阻力方向始终与实测运动方向相反。
- [ ] 为齿轮电机实现阻尼律：阻力方向始终与 IMU/速度反馈指示的运动方向相反。
- [ ] 在速度接近零时设置死区和滞回，避免阻力方向因噪声高速翻转。
- [ ] 低/中/高阻力档映射为固件常量；实际电流/力矩值必须通过台架标定后填写。
- [ ] `20 / 40 / 80` 在主动模式中作为速度保护/辅助上限，不直接当作恒定运动指令。
- [ ] 对双电机模式分别计算、分别限幅，不允许简单向两个电机写入同一个原始力矩数值。
- [ ] 双电机启动采用受控斜坡，避免同时阶跃加载导致机构冲击。
- [ ] 主动训练开始时清空旧目标、旧积分项和旧会话状态。
- [ ] 暂停时两台电机立即撤销主动阻力并进入安全停止状态。
- [ ] 继续时重新读取当前位置和运动方向，从当前状态平滑恢复，不追赶暂停前轨迹。
- [ ] 正常结束时力矩缓降至零，然后关闭主动模式。
- [ ] 紧急停止时跳过缓降，立即输出零力矩/禁能，并锁定为不可自动继续。
- [ ] 通信中断、IMU 失效、电机反馈超时、CAN 错误时自动撤销阻力。
- [ ] 实现组数判定：使用可靠的角度阈值、方向穿越和滞回判断一次掌屈+一次背伸，禁止仅按时间假计数。
- [ ] 对关节电机和齿轮电机分别维护有效反馈时间戳；选中的任一电机反馈无效则不得启动。
- [ ] 固件回传实时角度、速度、阻力档、实际输出、完成组数和停止原因。

## 被动模式保留与回归

- [ ] 合并主动功能时保留已验证的被动参数范围、开始、暂停、继续、停止与循环计数。
- [ ] 保留齿轮电机基于 IMU `roll` 的目标终点判断。
- [ ] 保留 Passive 角度范围 `-90°～90°` 及左右端点顺序校验。
- [ ] 保留循环完成后的自动回零、手动紧急复位和二者不同的状态提示。
- [ ] 主动/被动模式互锁：任一模式运行时，另一模式的开始命令必须被拒绝。
- [ ] Control 原操作界面与康复流程互锁，切换界面不得遗留电机使能或目标。
- [ ] 回归 Control 界面的 IMU 定位、正负角目标、停止和复位功能。

## 必须先完成的安全项

- [ ] 明确两台电机各自的硬件允许最大电流、连续力矩、峰值力矩和持续时间。
- [ ] 在 STM32 固件中设置独立于 UI 的绝对力矩/电流上限；BLE 不能突破。
- [ ] 设置绝对角度软限位，并验证安装方向反转时仍然生效。
- [ ] 设置速度上限、加速度/力矩变化率上限和启动斜坡。
- [ ] 设置反馈超时：超时后在确定时限内撤销输出并停车。
- [ ] 设置 BLE 心跳超时：上位机消失时不得保持阻力输出。
- [ ] 设置 IMU 数据有效性检查：全零、跳变、超范围、长时间不更新均判故障。
- [ ] 设置电机反馈有效性检查：CAN 超时、故障码、过流、过温立即停止。
- [ ] 紧急停止必须在 STM32 本地执行，不能依赖 BLE 界面或 ESP32 成功转发。
- [ ] 紧急停止后要求用户明确重新开始，禁止自动恢复。
- [ ] 复位只允许在 IMU 有效、角度范围合理且速度受限时执行；复位失败必须停车。
- [ ] 串口调试打印限频，禁止在控制中断或高频回调中阻塞打印。
- [ ] 保留可诊断停止原因：用户结束、训练完成、手动急停、自动复位失败、通信超时、传感器故障、电机故障。

## 分阶段验证与验收

- [ ] 阶段 1：断开电机动力，仅验证 UI 流程、命令帧、确认帧和状态机。
- [ ] 阶段 2：电机悬空、零阻力输出，验证方向、反馈、暂停、结束和急停。
- [ ] 阶段 3：仅关节电机，使用最低阻力和最低速度保护档验证阻力方向始终反向。
- [ ] 阶段 4：仅齿轮电机，使用最低阻力和最低速度保护档验证 IMU 方向及零速死区。
- [ ] 阶段 5：双电机最低阻力，验证两电机不会互相对抗或把手腕拖向极限位。
- [ ] 阶段 6：逐档标定低/中/高阻力，记录实际电流、力矩、温升和主观感受。
- [ ] 分别验证 `20 / 40 / 80` 三档具有可测量差异，并且不会突破硬件上限。
- [ ] 测试运行中拔掉 BLE、ESP32/MiddleBoard 传输线、IMU 和 CAN，确认都能安全停机。
- [ ] 测试外力强行改变机构位置后暂停/继续，确认从当前状态平滑恢复。
- [ ] 测试参数修改只在下一次新会话生效。
- [ ] 测试急停后复位、复位超时、再次开始的完整闭环。
- [ ] 对 Control、Passive、Active 三条路径分别完成不少于 20 次连续回归，无飞向极限、无旧命令重放、无通信锁死。
- [ ] 生成正式发布包前同时记录 BLE EXE、ESP32、中继板和 F407 固件版本及哈希。

## 建议实施顺序

- [ ] 第 1 步：冻结当前可通信版本并备份四端版本信息。
- [ ] 第 2 步：完成主动协议、确认帧和状态机，但保持电机输出为零。
- [ ] 第 3 步：完成固件安全限幅、超时和本地急停。
- [ ] 第 4 步：分别实现并标定两台电机的低阻力模式。
- [ ] 第 5 步：接通 UI 主动训练下发和实时状态显示。
- [ ] 第 6 步：完成中、高阻力与双电机联调。
- [ ] 第 7 步：完成全部故障注入、回归和发布验证。
