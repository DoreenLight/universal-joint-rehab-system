# 中间板六维力数据链路修复与离线验证

日期：2026-10-22。状态：源码修复、离线验证完成；未烧录，未验证现场故障消失。

## 修改边界

仅修改 `Driver/USART/usart3.c`、`usart3.h`、`usart4.c`、`usart4.h`。
保留115200/230400波特率、读寄存器地址、轮询/应答20ms参数和归零/保存命令；未修改电机板、控制、安全和上位机代码。
`baseline.json` 记录本轮修改前固件C/H文件摘要，测试核对仅允许四个文件变化。
`*.before` 和 `changes.patch` 提供本次修改前快照及差异；快照保留本轮之前已有的工作，不代表仓库初始版本。

## 三项修复

1. **连续接收与拼帧**：USART3 RX改循环DMA。IDLE不再停DMA；半满、全满和IDLE处理已收到的增量字节。USART3及RX DMA中断使用相同抢占优先级，避免两个接收处理互相打断。解析器跨块保留部分帧，按地址/功能码/24字节长度/CRC识别29字节六维数据，坏候选逐字节重同步。转发使用8槽环形队列（可用7帧），队列满时丢新帧并计数，不覆盖正在发送的数据。
2. **接收恢复**：UART/DMA错误记录错误码并申请恢复；主循环每20ms重试仅接收方向的中止/重启，检查返回值。恢复时清掉不完整帧，保留已经校验过的队列帧。初始化首次接收启动失败也进入重试。RX恢复不再调用会同时停止TX的HAL_UART_DMAStop。发送超时清标志前中止TX，避免HAL发送状态残留。
3. **有界转发**：UART4使用原100ms HAL超时；失败后记录并返回，不再进入无超时寄存器等待，也不重发可能已发出一部分的整帧。下一帧仍可尝试转发。打印重定向共用该有界发送接口；ISR或关中断上下文直接返回忙，避免HAL计时无法推进时等待。

非六维应答不作为六维数据转发；传感器写应答的事务确认没有在本轮新增，归零/保存仍沿用原状态机及超时行为。没有新增周期打印或诊断协议帧。

## RAM诊断计数

调试器可读 `g_uart3_diag`：

| 字段 | 含义 |
| --- | --- |
| rx_bytes | DMA消费者处理的字节数 |
| valid_frames / last_valid_tick | CRC有效六维帧数 / 最近接收时间，毫秒 |
| crc_errors | 完整六维候选CRC失败次数 |
| discarded_bytes | 重同步丢弃字节，包括不属于六维帧的应答 |
| queue_overflows | 队列满而丢弃的新有效帧 |
| forwarded_frames / forward_errors | 转发成功 / 失败次数 |
| uart_errors / last_uart_error | HAL错误回调次数 / 最近错误位图 |
| rx_restart_errors / rx_recoveries | 接收中止或重启失败 / 成功恢复次数 |
| response_timeouts / tx_timeouts | 等应答超时 / 发送忙超时次数 |

`g_uart4_diag`：`sent_frames`、`sent_bytes`、`send_errors`、`timeouts`、`invalid_requests`，覆盖UART4全部发送调用，打印字符也计作发送调用。
计数为32位RAM变量，重启清零、允许自然回绕；读取整个结构不是原子快照。单看接收字节增加不能证明有效六维帧增加。

## 验证

在仓库根运行：

```powershell
python 02-Firmware/02_MiddleBoard/tests/force_link/run.py
```

测试提取实际生产函数，以主机GCC的 `-Wall -Wextra -Werror` 编译，注入HAL结果和模拟DMA计数。233项断言通过，详见 `results.txt`：

- 28个拆包位置、逐字节输入、两帧粘包和转发字节一致性。
- 坏CRC、噪声后同步、队列满的明确丢帧计数。
- DMA半满/全满/跨尾部和重复IDLE无重复接收；IDLE不执行中止或重启。
- UART错误后中止失败、启动失败、后续重试成功和毫秒计数回绕。
- UART4错误/忙/超时没有整帧重试，后续正常帧可发送；中断上下文不阻塞。
- 发送忙超时清理、应答超时与后续轮询。
- 所有基线固件C/H文件检查：只有授权四个文件变化。

## 验证边界

未运行ARM/Keil编译、链接或设备测试。尝试用桌面GCC读取完整工程头文件时，在工程缺少 `cmsis_gcc.h` 处停止；主机提取测试不能替代目标构建。
真实DMA中断延迟、硬件串口错误恢复、RS485时序和100ms墙钟超时未测量。循环DMA要求及时处理半满/全满中断：115200下半缓冲约45ms；长时间屏蔽中断仍可能覆盖数据。本轮未改变全局中断或安全逻辑。
现场“归零后持续0”的确切断流位置仍未确认；这些修改消除已识别的代码风险，不代表已证实设备恢复。
