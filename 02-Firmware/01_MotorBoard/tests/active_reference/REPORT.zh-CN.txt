2. 三类数据的实际关系
Motor1：
- 视觉参考：g_actv_m1.pos -> g_actv_traj_pos -> 遥测0x0B -> Qt T波虚拟轨迹。
- 轨迹输入：力传感器 Mx 经原阈值/刚度逻辑得到 motor1_sudu，再积分到 Control_P_PID.In_val -> 遥测0x01。
- 反馈角度：IMU roll -> 遥测0x02，同时是 PID 的反馈输入。
Motor2：
- 视觉参考：g_actv_m2.pos -> g_actv_traj_pos_m2 -> 遥测0x1D -> Qt M2 T波轨迹。
- 规划位置曲线：g_m2_traj_deg -> 遥测0x11。
- 实际角度：motor_feedback.position * 57.29578 -> 遥测0x12，来自 CAN 反馈。
- 主动模式下真正发送的命令由力顺应分支的 m2_cmd_pos_rad 生成；该分支并不更新 g_m2_traj_deg，因此0x11可能保留旧规划值，不能当作当前实际发送指令。本轮未猜测修复这一原有问题。
参考位置没有赋给上述电机输入/控制命令。只替换参考曲线不会使电机自动跟随 S 形曲线，实时反馈路径保持原样。

3. 算法及计时
采用五次多项式：u=n/N，s(u)=10u^3-15u^4+6u^5，theta=from+(to-from)*s(u)。
起止速度和加速度为零，与恒定停顿段实现 C2 连续；不承诺 jerk 连续。反向行程用同一公式，浮点后半段用对称式减少端点消差。
角度、速度、停顿参数继续从 Motor1/2 原 getter 分别取得。speed 用于复现旧运动阶段的持续节拍数 N，不直接作为 S 形曲线的峰值速度。
N 通过相同 float 位置/速度操作复现旧到达判定获得，正反向分别缓存。未改 TIM2、主循环状态机、参考调用位置或 Qt 的计时逻辑。参考每次被原调度调用时前进一步；上传仍为每5个控制周期一次。
仍先在 limit1 停顿，再向 limit2 运动、顶部停顿、返回、底部停顿。启动、停止、重新启动沿用原入口。
固定配置下，旧算法在复现预算内收敛的阶段，运动/停顿/状态切换节拍数保持不变。原主动模式持续循环，没有有限周期数自动停止；未把被动模式的次数参数移用于主动训练。

默认两通道：limit1=-30度，limit2=30度，speed=30度/秒，pause=2秒。
- 每次运动223节拍，名义2.23秒。
- 每次停顿200次倒计数+1次状态切换，共201节拍，名义2.01秒。
- 周期848节拍，名义8.48秒；5周期4240节拍，名义42.40秒。
上述为阶段驻留时间。新曲线在运动最后一个节拍准确到达端点，原曲线可能提前一个采样到达，下一拍才确认；不声称每个位置采样或肉眼平台长度完全相同。
同时间同位移的五次曲线峰值速度为平均速度的1.875倍；默认参考峰值约50.45度/秒。这是视觉参考，不是改变电机最大速度设置。

4. 无法严格继承时长的情况
旧算法可能在目标附近进入精确重复的位置/速度循环。例如 -12度 -> 23度、17度/秒，约在23度附近反复偏差0.05度，始终达不到0.01度到达阈值。本轮双通道测试直接调用保存的原函数验证了4步完整状态重复。
这种旧轨迹本来没有有限运动时间，不能同时实现有限周期并声称严格保持原时长。本轮取消先前的208节拍替代值，返回0和 ACTV_REF_LEGACY_CYCLE，保持该视觉参考，不改变电机控制状态。
复现超过65536步而未能确认到达的配置，维持 ACTV_REF_TIMING_LIMIT；非有限参数、非法停顿转换维持 INVALID。失败结果缓存，避免每次调用都重算。
这些状态仅存在参考上下文中，现有 Qt 无对应错误提示。参考保持不等于电机停止，不应据此推断设备保护动作。
段内改角度/速度仍采用既有 S 形实现的冻结策略：当前段完成原端点，下一段采用新参数；pause 在到达时读取。与旧梯形算法每拍读取目标/速度不同，运行中改参的逐拍等价性不成立，也不能将视觉参考范围当作机械安全限位。
